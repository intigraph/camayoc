# camayoc-memory

Generated by `python3 scripts/memory_tools.py` from shapes/agent-memory.shapes.ttl and tools/memory/*.tool.json. Do not edit by hand; CI fails on drift.

## Rules

- Recall before you decide; record a human ruling the moment it is made.
- One tool per entity. Never write a memory file instead.
- A refusal names the missing field in plain words: supply it and retry. Never route around the shapes.
- Never put a secret in a record; a Reference takes the secret-store key name in `--secret-ref`.

## Surfaces

- Shell: `cy record <entity> ...` and `cy recall <entity> ...` (`camayoc` is the same command).
- MCP: add the server to `~/.codex/config.toml`, then use `record_<entity>` and `recall_<entity>`:

```toml
[mcp_servers.camayoc-memory]
command = "cy"
args = ["mcp"]
```

## Entities

### decision

Record one ruling on a scoped question: what was chosen, by whom, about what.

| Field | CLI flag | MCP argument | Required | Meaning |
| --- | --- | --- | --- | --- |
| chose | `--chose` | `chose` | yes | What was chosen, in one sentence. |
| by | `--by` | `by` | yes | Who ruled: a Person or agent entity (IRI or local name). |
| about | `--about` | `about` | yes | The entity the decision is about: host, repo, service, role, agent or person (IRI or local name). |
| topic | `--topic` | `topic` | yes | The registered memory topic the decision answers (cy topic add registers one). |
| over | `--over` (repeat) | `over` | no | An alternative that was not chosen; repeat for each. |
| rationale | `--rationale` | `rationale` | no | Why, in one or two sentences. |
| decidedIn | `--decided-in` | `decidedIn` | no | The board item or session the decision was made in (IRI or local name). |
| verbatim | `--verbatim` | `verbatim` | no | The ruling in the decider's own words. |

- Natural key: --about + --topic; the same key supersedes.
- Record: `cy record decision` (MCP `record_decision`)
- Recall: `cy recall decision [--about] [--topic]` (MCP `recall_decision`): Current decisions, optionally about one entity and topic.
- Recall: `cy recall decision --history <key>` (MCP `recall_decision_history`): Every version of one decision key, newest first, superseded ones included.

```bash
cy record decision --chose "Hostnames and crew names may appear in public repos and posts." --by "person-stiwi" --about "topic-public-launch" --topic "hostnames-in-public" --rationale "They are not secrets; history rewrites cost more than they protect."
```

### directive

Record a standing rule: one imperative sentence, who issued it, who it binds.

| Field | CLI flag | MCP argument | Required | Meaning |
| --- | --- | --- | --- | --- |
| rule | `--rule` | `rule` | yes | The rule, as one imperative sentence. |
| issuedBy | `--issued-by` | `issuedBy` | yes | Who issued the rule: a Person or agent entity (IRI or local name). |
| appliesTo | `--applies-to` | `appliesTo` | yes | Who or what the rule binds: an agent, CrewRole or repo, or 'crew' for everyone. |
| topic | `--topic` | `topic` | yes | The registered memory topic the rule governs (cy topic add registers one). |
| issuedOn | `--issued-on` | `issuedOn` | no | The date the rule was given, YYYY-MM-DD. |
| why | `--why` | `why` | no | Why the rule exists, in one sentence. |
| verbatim | `--verbatim` | `verbatim` | no | The rule in the issuer's own words. |

- Natural key: --applies-to + --topic; the same key supersedes.
- Record: `cy record directive` (MCP `record_directive`)
- Recall: `cy recall directive [--applies-to]` (MCP `recall_directive`): Current directives binding one agent, role or repo, plus crew-wide ones.

```bash
cy record directive --rule "Run disruptive deploys between 02:00 and 09:00 ET; never ask for a window." --issued-by "person-stiwi" --applies-to "crew" --topic "deploy-window" --issued-on "2026-10-27"
```

### handoff

Write the agent's one current handoff; each write supersedes the last.

| Field | CLI flag | MCP argument | Required | Meaning |
| --- | --- | --- | --- | --- |
| agent | `--agent` | `agent` | yes | The agent the handoff is for (IRI or local name). |
| next | `--next` (repeat) | `next` | yes | A next step pointing at a board item, PR or entity; repeat, 1 to 7. |
| waitingOn | `--waiting-on` (repeat) | `waitingOn` | no | What an item waits on; repeat, at most 7. |
| context | `--context` (repeat) | `context` | no | Context the next session needs; repeat, at most 3 lines. |

- Natural key: --agent; the same key supersedes.
- Record: `cy record handoff` (MCP `record_handoff`)
- Recall: `cy recall handoff [--agent]` (MCP `recall_handoff`): The agent's current handoff, if younger than its max age.

```bash
cy record handoff --agent "hammond" --next "Review camayoc PR for the cy CLI (board item aegis-gshu.10)" --context "Local quipu tests only; production shapes wait on a schema proposal."
```

| prefers | `--prefers` | `prefers` | yes | What the person prefers, in one sentence. |
| context | `--context` | `context` | yes | Where it applies: email, chat, code-review, document, artifact, form or travel. |
| topic | `--topic` | `topic` | yes | The registered memory topic (cy topic add registers one). |
| notWhen | `--not-when` | `notWhen` | no | When the preference does not apply. |

- Record: `cy record preference` (MCP `record_preference`)

### reference

Record where a system lives and how to reach it. Key names only, never secrets.

| Field | CLI flag | MCP argument | Required | Meaning |
| --- | --- | --- | --- | --- |
| subject | `--subject` | `subject` | yes | The system the reference points into: host, service, repo or tool (IRI or local name). |
| topic | `--topic` | `topic` | yes | What the reference is for: a registered memory topic (cy topic add registers one). |
| locator | `--locator` | `locator` | yes | Where it is: a URL, path, command or graph IRI. Never a secret. |
| secretRef | `--secret-ref` | `secretRef` | no | The secret-store key name that holds the credential. A key name, never a value. |
| access | `--access` | `access` | no | How to authenticate, in one sentence, without the secret. |

- Natural key: --subject + --topic; the same key supersedes.
- Record: `cy record reference` (MCP `record_reference`)
- Recall: `cy recall reference [--subject] [--topic]` (MCP `recall_reference`): Current references, optionally into one system and for one topic.

```bash
cy record reference --subject "system-seeds-board" --topic "board-access" --locator "sd show <id> (run locally; the board is seeds on quipu.svc)" --access "SHANTY_AGENT names the caller; no ssh needed."
```

# Camayoc agent primer

## What camayoc is

Camayoc owns what facts mean in a Quipu store: the ontology, the SHACL shapes
and the stored queries. `cy` (alias of `camayoc`) is its agent-memory tool:
one purpose-built command per memory entity instead of free-form memory files.
Every write goes through Quipu's shapes, and a refusal names the missing field
in plain words. Recall comes back through stored queries that drop superseded
and expired records.

## Agent workflow

1. Recall before deciding: `cy recall decision --about <entity>` or
   `cy recall directive --applies-to <agent>`.
2. When a human rules, record it at once: `cy record decision --chose ... --by ... --about ... --topic ...`.
3. A new record on the same natural key supersedes the old one; never delete.
4. Unknown topic? Register it: `cy topic add <name>`, then record.
5. Never put a secret in a record. A Reference stores the secret-store key name in `--secret-ref`.
6. Before you stop, write your handoff: `cy record handoff --agent <you> --next "..."`.

## Core commands

| Command | Use |
| --- | --- |
| `cy record <entity> --<field> ...` | Write one entity; refuses in plain words when a field is missing |
| `cy recall <entity> [filters]` | Current records, declared first, at most 50 |
| `cy recall decision --history <key>` | Every version of one decision key |
| `cy topic add <name> [--alias ...]` | Register a memory topic (a natural-key part) |
| `cy flush` | Replay records queued while Quipu was unreachable |
| `cy mcp` | Serve the same tools over MCP stdio (`record_<entity>`, `recall_<entity>`) |
| `cy prime [--brief] [--json] [--static]` | This primer plus live state |
| `cy record <entity> --help` | Every flag of one entity, from its shape |

## Writing safely

- Writes route to a plane by sourceKind: declared (a human said it), observed
  (measured), inferred (an agent concluded it). Inferred never overrides declared.
- Replacing a ruling by someone else needs `--supersede <iri>`.
- When Quipu is unreachable a record is queued and `cy flush` replays it.
