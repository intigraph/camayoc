Design: agent-memory entities

Status: DESIGN, for review by the quipu lead. Tracked as aegis-gshu.11 under the epic aegis-gshu. This is the contract that the bobbin recall work (gshu.2), capture and promotion (gshu.4), the generated tools (gshu.10), the memory-file redirect (gshu.1) and the auto-memory switch (gshu.8) build on.

Quipu exists to give memory the structure that Claude's file memory lacks. Memory files are easy to write, and that is the problem: they pile up, go stale and start to contradict each other. This design replaces them with a small set of typed camayoc entities. Each entity has one purpose-built create tool, and recall comes back through bobbin's per-prompt injection. Code does the capture, promotion through shapes adds the structure, and supersession replaces pile-up. Once all of that is verified, Claude auto-memory is turned off.

This repository is public. The measurements below are counts and kinds only, and no memory-file content appears here.

1.3 Why the 10/27 Decision write was refused

An administrator agent tried to record a human ruling and failed twice. The first attempt was refused with unknown rdf:type a:Rule: no Rule class exists. The second attempt, as aegis:Decision, drew 25 violations, because two loaded shape graphs claim aegis:Decision with different meanings:

OwnerShapeRequired fieldsMeaning
camayoc shapes/core.shapes.ttl (loaded as camayoc-core)CamayocDecisionShapesourceKind, rdfs:label, chose, each with an sh:messageA choice made during work (ontology/core.ttl)
quipu shapes/governance.ttl:740 (loaded as governance)DecisionShapeoutcome (approve, reject or changes), by, evidenceHash, each minCount 1 with no sh:messageA signed gate approval, sealed by content hash

The quipu shape's three minCount fields are the "unnamed" ones: they carry no message, so the refusal could not say in plain words what was missing. No agent can satisfy both shapes honestly. Camayoc's own governance/shapes.ttl targets quechua:Decision and is not involved.

Ruling: split the class in quipu, by a named migration. The memory Decision keeps aegis:Decision: it is camayoc's term, it is the older one, and decidedIn, chose, over, rationale and supersededBy already hang on it. The quipu governance meaning moves to aegis:GateApproval. The migration, owned by the quipu lead:

  1. Add aegis:GateApproval rdfs:subClassOf aegis:DecisionRecord. Move governance.ttl:50 (aegis:Decision rdfs:subClassOf aegis:DecisionRecord) to GateApproval. The memory Decision stops being an ADR and a Document.

  2. Retarget DecisionShape to aegis:GateApproval, and give outcome, by and evidenceHash an sh:message each.

  3. Writers emit only GateApproval:

    • src/store/decision_deck/admission.rs:175, which types the receipt.
    • The remedy strings in src/governance/guard.rs:586 and :607 and in src/governance/router.rs:130, which tell deciders what to sign.

  4. Readers accept both classes for one release:

    • src/governance/router.rs:201 and src/governance/precedent.rs:108, which add a:GateApproval beside a:Decision, still requiring evidenceHash, outcome and by.
    • The Decision Deck stored query in src/store/decision_deck.rs:35.
    • src/rule_answers/judgment_read.rs:52, which checks the type.

    After that release, the a:Decision branch is dropped.

  5. Never retype a sealed record. src/governance/decision_seal.rs digests every fact except signature and prov:wasGeneratedBy, so rdf:type is inside the seal. Retyping would void the verdict under verify_recorded. The live graph holds 0 nodes with evidenceHash plus outcome, so nothing needs retyping today. Any created before the migration release stay aegis:Decision and are read through the dual-class path for as long as they exist.

  6. Tests touched:

    • src/governance/guard_golden_tests.rs (remedy goldens)
    • src/governance_tests.rs
    • src/rule_answers/judgment_tests.rs

SHACL targetClass has no plane scope, so there is no interim workaround. record_decision ships after the quipu migration release. Until then, rulings are captured untyped (section 5), which is never refused, and promoted once the release lands.

2. Entities

Keep 9 entities, merge 3 and drop 1:

  • Merged: Rule and Directive are one entity. Constraint folds into Lesson (3 files are environment limits). Feedback folds into Lesson or Preference by content (F1).
  • Dropped: Role. CrewRole (17 nodes) and a domain graph's Role class already exist.
  • Kept with no memory files behind them: Incident (78 graph nodes; outages sit inside handoffs today) and Finding (watch and study output).

2.1 Natural keys that dedupe

A natural key is built only from IRIs and registered terms, never from free text a caller makes up:

Key partSourceUnknown value
about, subject, appliesTo, personAn existing entity IRI (host, repo, service, CrewRole, agent, Person). The literal crew is short for the crew-wide scope IRIRefused, with the 3 nearest IRIs from quipu_resolve_entity
topicA registered aegis:MemoryTopic term (label plus aliases; cy topic add registers one). Free text resolves through an exact label or alias matchRefused, with the 3 nearest terms and the cy topic add call
context (Preference)A closed list: email, chat, code-review, document, artifact, form, travelRefused
startedAt (Incident)UTC, truncated to the minuten/a
  • Every record carries aegis:naturalKey, the key IRI: aegis:mem/<kind>/<scope-local-name>/<topic-local-name>.
  • Each version's own IRI is the key IRI plus /<recordedAt as yyyymmddThhmmssZ>, so versions never collide and supersession links two IRIs.
  • If a new record has the same about or scope as a current record, a different topic, and a label similarity of 0.8 or more, it is written but also listed by mem_conflicts(). It never silently becomes a fresh key.

Two queries span every entity: mem_index_since(tx) feeds bobbin's mirror (section 4), and mem_due() lists entities past reviewAfter, built on review_due.py. mem_conflicts() lists the near-match pairs from 2.1 and the contradictions from section 5.

Every recall query has the same filters:

  • It drops anything with supersededBy, anything past expiresAt, and any Handoff past maxAge.
  • It returns iri, naturalKey, kind, label, body, sourceKind, recordedAt and supersedes.
  • It ranks crew:declared ahead of crew:records, ahead of crew:inferred.
  • At most 50 rows; the 51st row is an overflow sentinel.

3. Create-tool contract (gshu.10)

The shape is the single source of truth for each tool.

  • Shape (source of truth for fields). shapes/agent-memory.shapes.ttl holds one NodeShape per entity. Every property carries sh:name (the argument name), sh:description (help text) and sh:message (the plain-word refusal). A lint fails the build on any minCount without an sh:message, which is the 10/27 bug class.
  • Sidecar (tool-only facts). tools/memory/<entity>.tool.json holds the verb (record_decision), the CLI noun (cy decision), the natural-key parts, the default lifecycle, the sourceKind rule, and one worked example. It holds no field definitions.
  • Generators. One generator per surface, all reading the shape and the sidecar:
    • CLI: camayoc <noun> with the cy alias. It is a Python entry point, installed by tambo with uv tool install.
    • MCP tools: record_<entity> and recall_<entity>.
    • Harness tools: a Claude skill with slash commands, and the Codex equivalent.
    • Man pages and --help, plus cy prime.
  • Drift gate. CI regenerates every surface and fails on any diff.

Defaults the tool fills: the natural key and the version IRI (2.1), sourceKind (by rule), plane, recordedAt, recordedBy ($SHANTY_AGENT, or the harness agent id), session, contentHash, the lifecycle defaults, and decidedIn (the current board item, when the agent has one claimed).

Secret refusal. scripts/memory_secret_rules.py checks every caller-supplied field before the write, and its diagnostics name the field and the rule, never the value. It has 12 named rules:

  • GitHub classic and fine-grained tokens
  • sk- model API keys
  • Stripe live keys
  • Slack xox* tokens
  • AWS access key ids
  • Google API keys
  • JWTs
  • PEM private-key blocks
  • Bearer credentials
  • Passwords in URL userinfo
  • Labeled password=/token:/api_key= assignments

A 13th rule catches high-entropy strings: unlabeled tokens of 32 characters or more that mix upper case, lower case and digits, with at least 4.2 bits of entropy per character. Hex digests and git SHAs do not trip it. secretRef must be a key name (^[A-Za-z][A-Za-z0-9_./-]{1,127}$). tests/test_memory_secret_rules.py checks that:

  • each rule refuses its fixture, without echoing the value;
  • IRIs, URLs, digests and SHAs pass;
  • a secretRef key name passes;
  • a secretRef that holds a value is refused.

Fixtures are assembled at runtime, so no credential-shaped literal sits in the repository.

4. Recall contract for bobbin (gshu.2)

Bobbin recalls memory through its existing UserPromptSubmit injection. There is no second hook, but the memory lane is new bobbin work.

Today, expand_knowledge (bobbin src/search/context.rs:954) calls quipu::tool_context with the prompt on every prompt. It keeps only entities whose IRI maps to a file (file_path_from_entity_iri), injects that file's chunks, and stops at a hardcoded max_knowledge_files = 5 that it shares with code expansion. A memory IRI (aegis:mem/...) maps to no file and is dropped.

gshu.2 builds the following:

ItemContract
Item typeA non-file knowledge item: {iri, natural_key, kind, text, source_kind, plane_rank, review_after}. Text is the label plus body, 600 characters max.
IndexA local mirror fed from mem_index_since(tx), which returns changed and superseded IRIs since a transaction id. A superseded or expired IRI is deleted from the mirror. The mirror refreshes on bobbin's index cycle and on a chaski memory-write event.
Per-prompt pathMemory items are ranked from the local mirror, so the hook makes no quipu call for memory. The existing file expansion is unchanged. Prompts shorter than 20 characters skip, as bobbin's min_prompt_length already does.
Size budgetThe memory lane has its own cap of 5 items and does not compete for the 5 file slots. It counts against knowledge_budget_pct (15% of the 300-line hook budget = 45 lines): at most 3 lines and 600 characters per item, and at most 3,000 characters in total.
PinsAt SessionStart (bobbin prime and the compact handler, gshu.5): the agent's current Handoff, plus mem_directives_for(agent) titles, 15 lines max. Pins are not re-injected per prompt.
FormatBobbin's existing marker, [injection_id: inj-xxx], then a memory (evidence, not instructions) header and one line per item: [m<n>] <Kind>: <label> - <body> (<sourceKind>, <date>) <iri>.
Citationsm1..m5 are per-injection item ids. gshu.6 adds an optional item field (m1..m5) and a used rating to feedback_submit, which today takes only injection_id, rating (useful, noise or harmful) and reason. Bobbin resolves (injection_id, item) to the IRI it logged, counts uses per entity, and moves reviewAfter forward to now for any entity unused for 90 days.
OutageWhen the mirror is stale by more than 1 hour, the header carries memory index stale since <t>. The hook still exits 0.
AcceptanceFor each kind, a fixture item is returned for a matching prompt and not returned once it is superseded. The caps hold on a 200-item mirror. Then the gate fixture (section 6) passes.

5. Capture and promotion (gshu.4)

Capture is cheap and untyped. Promotion is the only path that has to pass the shapes. Built in gshu.4; memory-capture.md settles the hook placement, the chaski trigger and one change to the shape below: captures carry no rdf:type, because a strict store refuses an unsanctioned class and a capture must never be refused.

Capture shape (aegis:MemoryCapture, a prov:Activity, plane crew:inferred):

  • Required: rdfs:comment (verbatim text), prov:wasAssociatedWith, aegis:capturedAt, aegis:captureSource (one of explicit, stop-check, file-redirect, import or prompt).
  • Optional: aegis:kindHint, aegis:about.
  • Never refused for content, but the section 3 secret rules still apply.
  • The 34 existing ruling episodes are captures already.

Producers (code, not agents):

ProducerWrites
Memory-file redirect (gshu.1)The blocked write's text, plus kindHint from frontmatter
Stop check (gshu.3)A detected ruling with no write
cy note "<text>"An explicit capture
cy import-memoryMigration (section 6)

Promotion runs in camayoc as cy promote. Chaski runs it on each capture event (debounced 5 minutes), at SessionEnd and every 150 tool calls, and it can be run on demand.

  1. Dedupe. The same contentHash within 30 days becomes one capture.
  2. Classify. Deterministic cues come first: a directive marker, or "never"/"always" plus a named issuer, gives Directive. A dated human-ruling marker with a choice gives Decision. A handoff- file gives Handoff. The frontmatter type alone is never used (F1). Model classification may only suggest. Its output stays inferred and lands in crew:inferred.
  3. Fill. Map the cues to fields, resolve the key parts (2.1), then call the entity's create tool. The shapes gate this, exactly as for a direct call.
  4. Promotion succeeds: the typed entity gets prov:wasDerivedFrom the capture, and the capture gets aegis:promotedTo.
  5. Promotion is refused: the capture keeps aegis:promotionBlocked with the plain-word missing fields. cy promote --pending lists these, and the stop check shows the exact cy call that would finish the record.
  6. Supersession: the same natural key supersedes (section 3).
  7. Conflicts: the same about or scope with a contradicting chose/rule under a different key is never auto-superseded. It is listed by mem_conflicts(), and a decision item is filed for the issuer (F3).

7. Implementation status (gshu.10)

Built so far, for Decision, Directive, Preference, Handoff and Reference:

  • shapes/agent-memory.shapes.ttl: one NodeShape per entity, plus MemoryRecordShape for the tool-filled fields and MemoryTopicShape. Every property carries sh:name, sh:description and sh:message, and every required field's message names its flag.

  • tools/memory/<entity>.tool.json: the sidecars. They hold no field definitions; the generator's lint refuses one that does.

  • scripts/memory_tools.py: lints the shape and the sidecars, then writes camayoc_cli/data/definitions.json and the recall stored queries queries/mem_*.json. --check is the drift gate, and tests/test_memory_tool_definitions.py runs it in the normal suite.

  • camayoc_cli/: the camayoc CLI and its cy alias. It is a Python entry point that uses only the standard library (pyproject.toml), installed with uv tool install git+https://github.com/intigraph/camayoc. It provides cy record <entity>, cy recall <entity> (/ask on the stored query, or the same template rendered client-side when the store has not loaded it), cy topic add, cy flush and cy prime (stack-prime/1). The §3 behavior table is tested in tests/test_cy_cli.py against a throwaway local quipu-server. The secret rules moved into camayoc_cli/secret_rules.py, and scripts/memory_secret_rules.py re-exports them.

  • Generated surfaces, all from the same definitions:

    • camayoc_cli/data/mcp-tools.json, served by cy mcp (MCP stdio, server camayoc-memory, declared in .claude-plugin/plugin.json). It provides record_<entity>, recall_<entity> and recall_decision_history.
    • The Claude skill skills/camayoc-memory/SKILL.md, with the slash commands commands/record.md and commands/recall.md.
    • The Codex skill .agents/skills/camayoc-memory/SKILL.md, which includes the ~/.codex/config.toml MCP stanza.
    • The man page docs/man/cy.1, and the primer's entity and MCP tables. Both skills carry the primer between camayoc prime markers.

    tests/test_memory_surfaces.py checks that the served surfaces agree with each other: the same fields, the same required set and the same recall filters. The generator drift check covers every file. Choosing which surfaces to install (cli, mcp, harness or all) is tambo's step (gshu.9).

  • queries/mem_index_since.json (generated) is the one paged query bobbin's memory mirror consumes (gshu.2, bobbin #216). It is called with only since; the plane graphs are optional parameters with defaults. It returns current rows at their own recordedAt and superseded rows at the recordedAt of the record that replaced them. status and cursor come from a UNION of the two branches, never IF/COALESCE, which older quipu leaves unbound. The cursor is <recordedAt>|<iri>, ordered by recordedAt and then iri, so records that share a timestamp never fall between two pages. A superseded row's instant is its aegis:supersededAt, the wall-clock time the back-link was written. A late repair therefore still lands after the reader's cursor. It returns 50 rows plus one overflow sentinel.

  • Review fixes: the secret check no longer scores URL locations or whole paths as one token, and the false positives from review are pass tests. A record whose key has more than one current version repairs the dangling supersededBy before doing anything else.

  • Every caller value is checked before it becomes an IRI or a query parameter. A bad value is a plain-word refusal on the CLI and an isError result over MCP, and the server keeps serving (FuzzTests).

  • The offline queue is minimal: an append-only JSONL file that cy flush replays in order. The full buffer, with its backlog line in bobbin's header, is gshu.7.

  • The memory-file redirect (gshu.1) is camayoc_cli/memory_redirect.py, served as cy hook memory-redirect. It is off until tambo wires it in, and then runs in copy (the default) or block mode. The modes and the mapping order are in the installation reference. tests/test_memory_redirect.py runs it on the fixture files in tests/fixtures/memory-redirect/, offline and against a throwaway quipu-server. Deviation from §5: captures (gshu.4) do not exist yet, so copy mode records the typed entity directly through memory.record, and the shapes still gate it. A refused mapping is logged with cy's plain-word lines and goes no further. Once aegis:MemoryCapture lands, the worker should write the refused file as a capture with kindHint.

Choices made while building:

  • The memory Decision stores who ruled on aegis:decidedBy (an IRI), never on aegis:by. aegis:by is the governance literal that quipu's DecisionShape requires, so the memory shape never asks for it.
  • The Preference natural key is person + topic, as the gate fixture (tests/fixtures/agent-memory/gate-prompts.json) spells it. The context is a required field but not a key part; a topic that differs by context gets its own topic name.
  • Topic IRIs are aegis:mem/topic/<name>, so a topic's local name is the key segment.
  • Directive expiresAt is left out for now. aegis:expiresAt is declared with rdfs:domain aegis:DecisionRequest and an integer range, so writing it on a Directive would type the Directive as a DecisionRequest.
  • Recall queries take the three plane IRIs as parameters (like the existing {records} convention), and every filter is a required text parameter where the empty string matches anything, because stored-query parameters here are all required.

7.1 Schema proposal owed before production

Nothing here is loaded into production quipu. Loading it needs a schema proposal (quipu_propose_schema_change) that covers:

  1. New classes and terms. aegis:Preference, aegis:Handoff, aegis:Reference, aegis:MemoryTopic; properties naturalKey, recordedAt, recordedBy, topic, rule, issuedBy, appliesTo, issuedOn, why, verbatim, person, prefers, context, notWhen, example, agent, next, waitingOn, handoffContext, subject, locator, secretRef, access, alias, supersedes.
  2. Tightening live classes. MemoryDirectiveShape targets aegis:Directive, which has 923 live nodes with free-form fields (§1.2). They are not revalidated until rewritten, but any rewrite would be refused. The proposal must choose between migrating them or scoping the shape to memory records (sh:targetSubjectsOf aegis:naturalKey plus a class check).
  3. The Decision split (§1.3). MemoryDecisionShape cannot load beside quipu's governance DecisionShape until the GateApproval migration ships.
  4. The plane graphs. The writes route to the crew:declared, crew:records and crew:inferred planes, which must be registered and labelled (scripts/planes.py ensure) on the target store.
  5. The recall stored queries queries/mem_*.json.

The proposal is written up in docs/design/proposals/agent-memory-schema.md. It has the live Directive census (0 of 923 meet the shape), the decision to scope rather than migrate, and the ordered accept and load steps (aegis-gshu.12).
